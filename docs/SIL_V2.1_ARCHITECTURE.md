> "公民体系"与下一步工程准则。可作为下一步（大仓库校准、提速重构）的指导纲领。
>
> 前置阅读：`docs/V2_HANDOFF.md`、`docs/agent_exploration_report.md`、`ARCHITECTURE.md`。

## 1. 背景概述

基于对 V2 版本交接报告的深度复盘，系统已成功使用**真实 codebase-memory 图谱 +
真实 LLM** 端到端跑通了并发测绘。我们针对运行中暴露的三类问题做了充分探讨并形成共识：

1. **工程精度问题**（短名歧义、动态边丢失、小仓库指标退化）；
2. **架构诊断的"链式一致性"哲学难题**（污染父节点的健康叶子是否连坐）；
3. **"小型工具函数"引发的可视化噪音**（纯透传工具打断业务主线）。

本文件将这些高维讨论结论沉淀为 V2.1 的公民体系与工程准则。

## 2. 工程层面的避坑与校准共识

- **防幻象交叉**：底层强制使用 `qualified_name` 精确匹配，彻底解决短名歧义
  （如多个独立 `_run` 撞名）导致的假阳性交汇。
- **防骨干断裂（动态补边）**：静态图谱无法解析 `obj.method()` 型动态分发，导致主线断裂。
  共识机制为"**源码正则提取 + 唯一名约束 + 置信度衰减**"，在 Agent 层补偿调用边。
- **小规模仓库的指标退化（Concordia 修正）**：在微型代码库中（节点总数 `S≈2`），
  基于 `Fan-in / (S·ln S)` 的相对扇入指标会急剧退化，极少调用即可使比率飙升。
  共识：必须引入**绝对扇入下限 `fanin_min`**，弥补纯数学模型在微小项目中的缺陷。
- **并发异常处理**：警惕 bare `except` 吞噬关键错误（如 `VERDICTS` 导入失败导致评审 LLM
  被静默跳过、退化为死板兜底规则）。关键导入/解析失败必须可见（`CODEMAP_DEBUG` 门控）。

## 3. 架构哲学层面的终极判例：`_decode` 的"链式一致性"张力

**问题**：当父节点 `parse_jwt` 被判为"违规摄取半成品"的**职责污染**时，其内部调用的
高扇入叶子节点 `_decode` 是否应当被"连坐"标红？

**判例共识：拒绝连坐，接受 LLM 的独立判断，但必须提供上游上下文。**

- 污染（犯罪现场）发生在 `parse_jwt` 的**边界**上；`_decode` 本身依旧是健康的底层算法库。
- 在代码地图上：**父节点标红警告，子节点标金高亮**。
- 这向 Agent / 开发者传达了极其精确的重构信号：
  > "保留底层基建不变，剥离或重构不合理的业务耦合边界。"

> 注：此判例**取代** `V2_HANDOFF.md` §6.1 中"悬而未决"的待定项。结论是：评审 LLM 仍逐节点
> 独立判断（不强制下传父节点 verdict），但评审输入需携带上游已判定上下文作为佐证。

## 4. 公民体系 2.1 升级版 (The Code Factory Citizen System V2.1)

为彻底解决"把公共原语误判为污染"的问题，并消除小函数打断业务主线造成的视觉噪音，
代码库公民被更严格地细分为以下等级：

| 公民 | 定义 | 行为 / 渲染 |
|---|---|---|
| **Source（涌现点）** | 原材料进入系统主线的起点 | 主线起点 |
| **Processor（私有中间环节）** | 专属于某主线的私有业务逻辑 | 被跨线调用即为**职责污染 (Tangling)** |
| **Sink（稳定沉淀点）** | 数据产生副作用或状态持久化的合理终点 | 多线在此交汇视为**健康交叉** |
| **Heavy Shared Utility（大型公共枢纽 · 已飞升节点）** | 高相对扇入 + 适度扇出的复杂基建（数据库连接池、鉴权中间件） | 渲染为**发光金色"大型换乘枢纽"** |
| **Lightweight Utility / Dual（小型内联基建 · 透明转换器）** | 极高相对扇入但**零扇出**的纯工具函数（如 `format_date`） | 物质流中扮演**透传/转换 (Pass-through)**；探索与渲染上**降维折叠**为管线滤镜，**绝不作为独立站点打断主线** |
| **Barrier / Stub（外部存根 · 防爆墙）** | 第三方库不展开源码 | 仅靠边缘出入边判为 **Sink**（接地线，停止）或 **Dual**（转换器，切换追踪物并继续） |
| **God Node（上帝节点 · 严重污染 · 反面典型）** | 高相对扇入**且**高扇出，伪装成基础设施的系统级纠缠点 | 标红严重告警 |

**核心区分轴**：
- *扇出* 把 **Heavy Shared Utility（适度扇出）/ Lightweight Utility（零扇出）/ God Node（高扇出）** 三者分开。
- *归属/可见性* 把 **Processor（私有）vs Shared Utility（公共）** 分开——这是"健康复用 vs 职责污染"的判定关键。

## 5. 探索效率的降本提速共识

当前小型代码库 Dogfooding 仍需数分钟，瓶颈主要在 **LLM 串行 I/O**。提速策略：

1. **批量探路 (1-hop Flattening)**：抛弃逐个子节点询问，一次性拉取当前节点所有下游签名
   （Ego-graph 展平），向 LLM 发起**单次请求**批量判定。
2. **静态快速通道**：利用图谱物理特征（如**扇出为 0 必是 Sink**）或标准库黑名单执行
   本地硬拦截，跳过 LLM 咨询。
3. **延迟批量评审 (Deferred Batched Verdict)**：各并发主线**无锁狂奔打卡**；待探索彻底收敛后，
   用一条 SQL 聚合所有交叉节点，发起**最后一次 LLM 请求**出具批量诊断报告。

## 7. 与 V2 的差异速记

- **新增公民两类**：`Heavy Shared Utility`（金色枢纽）与 `Lightweight Utility / Dual`
  （透传折叠），区分轴从"sink vs processor"升级为"扇出量级 × 归属可见性"。
- **`_decode` 判例落锤**：父红子金，拒绝连坐 —— 关闭 V2 §6.1 的悬而未决项。
- **提速成为一等公民**：批量探路 / 静态快速通道 / 延迟批量评审三板斧。
- **校准被列为 P0**：现有阈值是小仓库上"拍"的，必须在大仓库上重定。
